01 / The experiment

From predicted tokens to robot motion.

Can a small controller improve a large vision-language-action model—without retraining the VLA?

This project explores that question with pi0-FAST, Physical Intelligence’s autoregressive robot policy. I fine-tuned the model on two manipulation datasets, then compared three approaches: the VLA alone, the VLA with action smoothing, and a frozen VLA with a learned residual controller followed by smoothing.

The experiments ran on a single NVIDIA RTX 5090 with 32 GB of memory. Training, evaluation, and model checkpoints are available for others to inspect and build on.

Two environments, different manipulation challenges

  • LIBERO-Spatial: ten language-conditioned tasks involving spatial relationships, trained on 432 demonstrations and 52,970 timesteps.
  • MimicGen Square D0: square-nut assembly, trained on 1,000 demonstrations and 153,477 timesteps. The robot must pick up the nut, transport it, align it, and insert it onto a peg.

02 / How it works

One policy. Three ways to execute it.

01

VLA policy

Images, language, and robot state go into pi0-FAST. The model generates tokens for a ten-step action chunk.

02

Residual correction

A small MLP reads features from the frozen VLA and adjusts the six motion dimensions. The gripper stays unchanged.

03

Action smoothing

An exponential moving average smooths successive motion commands before the simulator executes them.

The VLA architecture

Fine-tuning the VLA

Both policies start from the official pi0_fast_base checkpoint and retain FAST+ action tokenization. LoRA adapts Gemma while the SigLIP vision backbone is fully fine-tuned. Training uses masked token cross-entropy.

FAST applies a temporal DCT to each action dimension, quantizes the coefficients, and compresses the flattened sequence with BPE. Decoding recovers a 10 × 7 action chunk: six motion values plus one gripper value at each timestep. Evaluation executes five actions before requesting a new chunk.

See the training-loss equation from the presentation

Learning a small correction

The selected controller combines mean-pooled Gemma features from layers 4, 8, 12, and 18. Per-layer normalization and learned softmax weights produce a shared feature vector. An MLP predicts ten steps of six-dimensional residual motion.

acorrected = aVLA + Δacontroller

The frozen VLA generates actions and intermediate features on demonstration observations. The controller learns the difference between demonstrated and VLA motion using masked, normalized mean squared error. It does not change the VLA weights or predict the gripper.

Smoothing the executed actions

ãt = λãt−1 + (1 − λ)acorrected,t

Smoothing follows residual addition and applies only to the six motion dimensions. The first action is unchanged; history resets each episode. The selected settings are λ = 0.2 for LIBERO and λ = 0.3 for MimicGen.

How to read these results

These are selected development-evaluation runs, not an untouched test benchmark. The final LIBERO EMA control and trained controller used the same decoding validation and initial-state index protocol, but cross-run repeatability remains unresolved. The observed differences are not established causal gains, and the historical runs are not a fresh six-way comparison under one decoder version.

What this experiment suggests

  • Inference-time changes are worth testing. Constant smoothing and a compact learned residual both produced promising selected results without changing the VLA at evaluation time.
  • Lower offline loss does not guarantee better rollouts. A longer-trained MimicGen controller reduced validation MSE slightly but performed worse in the simulator.
  • Model selection needs closed-loop evaluation. Longer VLA training and more controller feature layers did not consistently improve success.

The earlier LIBERO 97% run used a zero-output controller and is excluded. The published LIBERO controller is the verified nonzero head used in the final 96% run.
